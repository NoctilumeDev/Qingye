## 负载与成功标准

[压测脚本](../scripts/load-test.py)只接受 loopback 地址，拒绝凭据型 URL、代理跳转及业务写接口。先核对青野健康响应和演示登录开关，通过实际 HTTP 演示登录获得 64 个不同会话；每个 worker 使用独立会话、一个 HTTP 连接及最多一个在途请求，各级复用这些会话。独立会话避免同一助手会话的并发请求互相废止结果凭据。

11 路请求按确定顺序等权轮换，各 worker 从不同位置起步：

| 请求 | 读取范围 |
| --- | --- |
| `GET /api/activities` | 公开活动首页，最多 20 条 |
| `GET /api/equipment` | 器材目录，最多 100 条 |
| `GET /api/clubs` | 社团目录，最多 100 条 |
| `GET /api/announcements` | 当前身份未归档公告首页，最多 20 条 |
| `GET /api/me` | 当前会话本人资料 |
| `GET /api/activities?scope=mine` | 本人未取消报名活动首页，最多 20 条 |
| `GET /api/loans` | 当前身份可见借用，含其管理社团的记录，最多 200 条 |
| `POST /api/assistant/query`，`ACTIVITIES` | 固定活动查询，`ANY` 时间，首页最多 10 条 |
| 同上，`EQUIPMENT` | 固定 `ALL/CURRENT` 库存查询，首页最多 10 条 |
| 同上，`MY_REGISTRATIONS` | 会话本人报名，`ANY` 时间，首页最多 10 条 |
| 同上，`MY_LOANS` | 会话本人借用，`ANY` 时间，首页最多 10 条 |

每个响应必须满足 HTTP 200、JSON 类型、整数业务码 `0` 及预期业务结构。列表逐行检查有效 ID 和相关业务字段类型；本人资料核对身份 ID；公告核对分页、版本和标题；四门查询要求 `QUERY`、预期意图、`FACETS`、`businessRead=true` 和完整四门轨迹。HTTP 200 中的业务拒绝、非查询结果或结构缺失均计为失败。脚本不读取或输出会话令牌，不保存完整业务回包。

登录、预检和每级 5 秒预热不计入测量。每级在 30 秒内持续发起闭环请求，停止发起后等待在途请求结束；吞吐分母包含这一排空时间。p50/p95/p99 按所有已完成尝试的客户端耗时使用 nearest-rank 计算；本轮没有失败样本。超时为每次 socket 操作 10 秒，不自动重试。任何失败会保留该级结果、非零退出并停止后续级，不靠提高超时取得成功。

在这组数据和这台机器上，64 个在途请求能完成本轮 30 秒测量，并不表示 64 个在线用户上限或可承诺的线上 SLA。生产环境需要用实际数据分布、独立负载机、目标延迟和可接受错误率重新测量。
