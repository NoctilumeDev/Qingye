## 修正

- 社团返回跟随真实入口，不把所有返回都指向发现页。
- 发现和工作台返回时刷新已加载的完整页数，避免长列表突然缩回第一页；筛选变化仍从第一页开始。
- 工作台保留所选社团的 ID，过时的异步请求不能覆盖新的页签 / 选择。
- 修改称呼使用青野自己的输入框与按钮样式，覆盖所有账号；原先只修改系统确认色并没有解决弹窗整体违和的问题。
- 编辑社团、活动、器材时使用编辑标题，避免修改现有资料却仍显示“创建 / 发起”。

## 证据与限制

原生截图及逐项结果在 `docs/design/navigation/`。自动化通过真实页面输入、点击与原生返回；活动卡内部选择器不可直达时调用组件真实 `open` 事件方法，底部导航跨组件检查调用真实切换方法，没有注入业务页面数据。

导航与弹窗初始回归为 22 项，后续反馈处理增至 26 项，十页 WCC / WCSC 编译通过。独立用户测试及新一轮后端 MySQL 并发 / 权限测试结果见 [用户测试与反馈](USER-TEST-20261001.md)。代码冗余审计按用户指定顺序在第一轮提交后进行，不由这份导航记录宣称完成。

这份记录只覆盖本机模拟器；可见返回按钮及输入、取消、保存操作有明确标签。手机键盘避让、辅助技术焦点 / 读屏及真机效果仍需要独立验证，不能从截图推断完整可访问性合规。真实微信登录、外部模型及正式上线不在本轮范围。
