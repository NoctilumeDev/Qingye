## 完整解析依赖检查

```powershell
python -B scripts/check.py dependencies
```

此命令需要访问 Maven 仓库、OSV 和 GitHub 工具下载地址，不包含在 `quick` / `all` 的本地测试组合里。
CI 在现有必需的 H2 job 中执行，PR、main push、手动运行及每周重查使用同一入口。
定时工作流只有合并到默认分支后才会生效；配置存在不等于已取得定时运行证据。

检查器重新生成 dependency tree 与 CycloneDX SBOM，再运行 OSV；不消费历史成功报告。
使用 Maven Dependency Plugin `3.11.0`、CycloneDX `2.9.3`、OSV-Scanner `2.7.0`，
Windows/Linux x64 扫描器下载与缓存均检查固定 SHA-256，不支持的平台拒绝执行。

- 分母是项目完整解析后的 compile/runtime/test/provided/system 依赖，包含传递依赖。
- dependency tree、SBOM 和扫描报告的包集合必须相同；空报告、漏包、重复包、错误退出码均拒绝。
- [审查清单](dependency-policy.json)记录 93 个包的版本、作用域及许可声明，以及 31 条公告的内容指纹。
- 新公告、公告评级/内容变化、未经解释消失的公告、包版本/作用域/许可变化均需维护者审查，不能自动重写清单。
- 原分诊引用的 11 个后端源码/配置文件发生变化，也需复核受影响判断；哈希只负责发现变化，不负责证明语义仍成立。
- 当前 25 条条件性不适用、6 条未解决保持原状态；输出明确计数。门禁通过不是“零漏洞”或风险接受。

每次运行使用独立的 `backend/target/dependency-audit/run-*` 目录。CI 尝试保留 tree、SBOM、
OSV 原报告和运行坐标；缺少某阶段报告代表该阶段未取得证据，不拿上一次绿灯补齐。
扫描器报告有公告时的退出 1 与工具执行失败分开处理。网络失败不会回退成通过。
维护者查看变化涉及的源码、公告与许可后，才可通过 PR 更新清单；历史风险条目及首败不删除。

此检查不包含 Maven 构建插件自身的传递依赖、操作系统包、Git 历史或未被工具识别的漏洞。
Actions 仍固定提交，PR 依赖增量审查继续保留；它们不是同一范围。

## 敏感信息检查的范围

[凭据特征检查](../../scripts/check-secrets.py)随 hygiene 执行，扫描当前 Git 跟踪的 UTF-8/UTF-16 文本。
PEM 私钥头、GitHub token、`sk-` 类密钥和 Slack token 的有限特征命中会拒绝；
只输出路径、行号和规则，不输出值。不允许整目录豁免或在日志里回显候选凭据。
输入无法读取/解码、跟踪路径逃出仓库、未扫描任何文本均不能通过。

这是有限特征护栏，不是“仓库没有秘密”的证明：任意格式的口令、普通数据库密码、
二进制/压缩内容、图片和历史提交不在其完整检出能力内。现有私有文件名门禁与人工 diff 审查继续保留。
测试使用动态拼接的假 token，并检查正常/优化模式都拒绝且日志不含值；没有向外部验证 token。
若发现真实泄露，应撤销凭据并另行处置历史暴露，不以删掉当前文本代替修复。

## 覆盖盲区的有限复核

在上述生产源码上，本地 H2 基线为 76 项测试，JaCoCo 行 `978/1071`、分支 `529/713`。
这是本批补测试前的观察，不是新版本永久数值；最终值以对应 CI 工件为准。

| 路径 | 已有见证与未覆盖边界 | 本批处理 |
| --- | --- | --- |
| 登录与会话 | 已有错误签名、禁用账号、撤权请求链；AuthService 仍有 19 行未覆盖 | 补[认证反例](../../backend/src/test/java/cn/qingye/AuthBoundaryTest.java)：缺失/过短签名密钥、禁用演示入口、到期边界、不同密钥及非法 token；不调用微信 |
| RabbitBridge | 53 行中 38 行未覆盖；默认测试关闭 MQ | 保留真实连接、确认、消费与故障恢复盲区；不以 Mock 或只读检查冒充协议安全结论，也不扩大部署研究 |
| QueryCache / ExternalHttp | 缓存失效降级、模型非法参数、响应失败及完整正文截止时间已有本地见证 | 保留真实 Redis、外部网络及真实模型质量边界；不重跑付费实验 |
| 权限、容量与数据库 | 已有容量扫描、锁后撤权及回滚测试；本地 H2 不替代 CI MySQL | 保持独立 MySQL 必需检查，不降低规则，也不新增任意覆盖率阈值 |
| 调度、启动及异常支路 | TaskWorker、应用启动和部分异常路径仍有未覆盖行 | 记录有限性；未据此发现已确认缺陷，不为覆盖率数字扩展功能或另造环境 |

维护者在相关路径发生变更时复核这些边界。没有把“未覆盖”自动判为漏洞，也没有把它改写成已验证。
本批新增测试只约束已有行为；生产源码与六条 RabbitMQ 候选状态不变。
