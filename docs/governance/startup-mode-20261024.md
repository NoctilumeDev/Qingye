# 启动配置优先级复验（2026-10-24）

## 问题与范围

基线为 `52917105c0c99b2654f0869657df249b3eaaecd1`（HTTP 上限修复已合并）。
`scripts/start.ps1` 先加载 `local.ps1`，但未传 `-RealWechat` 时又无条件设置
`QINGYE_DEMO=true`，覆盖了调用者明确设置的 false。

本次仅修正这一优先级：`-RealWechat` 优先关闭演示，其次使用加载本机配置后的显式环境值，
未配置才保留原来的演示默认值。Redis、MQ、监听地址、构建和 Java 启动参数不变。
不改变登录接口、业务权限或四道门，也不修改依赖、历史证据或安全政策。

## 同条件对照

[启动测试](../../scripts/tests/test_startup.py)复制真实启动脚本到独占临时目录，
以 PowerShell 执行，并用命令替身记录交给 Java 的最终环境与参数。
不调用真实 Maven/Java、不启动服务、不读取用户的 local.ps1。

| 条件 | 原脚本 | 候选 |
|---|---|---|
| 显式 false，回环或全网卡地址 | 被覆盖为 true（2 个子用例） | 保留 false |
| local.ps1 设 false，外层环境为 true | 被覆盖为 true | 保留 false |
| 显式 false，同时启用中间件开关 | 被覆盖为 true | 保留 false |
| 显式 false，经过离线构建步骤 | 被覆盖为 true | 保留 false |
| 未配置、显式 true | 保持演示 | 保持演示 |
| -RealWechat，无配置或 local.ps1 设 true | 关闭演示 | 关闭演示 |

同一测试源码下，原脚本执行 8 项测试，5 处预期断言失败；候选 8 项通过。
维护测试的普通与优化模式、现有必需 CI 继续独立核验，不能由此表代替执行结果。

第一次测试夹具把开关作为字符串数组传递，导致正常对照的 SkipBuild 未绑定；
该次属于夹具失败，不能作为产品反例。修正为命名参数绑定并保留构建次数等断言后，
才取得上表的有效旧版对照。原始输出和夹具失败说明另行保留，没有删除失败或放宽断言。

## 仍然未知

也不证明真实微信登录或学校部署可用。演示身份选择仍是演示能力，
监听 0.0.0.0 不自动关闭演示。README 说明受信任网络边界与关闭演示的方法。

本事项所有者为青野维护者。候选通过并合并后，配置覆盖问题可以关闭；
实际网络条件仍保留未验证，第三轮其他业务交接审查不随本项自动通过。
