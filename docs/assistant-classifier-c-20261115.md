# 第二门方案 C：批量分类后一次整体复核

方案 C 用于检验一次全局复核能否在有限等待时间内提高第二门的业务分类正确性。

它不启动青野后端、不连接数据库、不进入第三、第四门，也不产生查询授权。生产提示词和生产代码不修改。

## 固定流程

1. 第一次调用完全复用方案 A 的批量分类提示，返回 1 至 4 个六字段子项或 `OVERFLOW`。
2. 第二次调用同时读取原始请求与第一次分类，对有效目标、改口撤回、条件归属、否定排除、关联关系和必要不确定进行一次整体复核。
3. 第二次输出同一批量协议，作为 C 的最终分类。不得逐项循环，不得开启第三次调用。
4. 第一次输出不符合协议时停止，不把无法解析的内容交给复核模型猜测。
5. 初判与最终分类都保留；纠正、破坏和净收益必须按原始任务进行业务裁决，不能由模型自评。

## 时间与调用边界

- 每个任务最多两次模型调用；无自动重试。
- 每次调用上限 18 秒。
- 两次调用共享 18 秒模型预算；第二次只获得剩余时间。
- 超过预算时记录为预算耗尽，未经完成的复核不能算成功。

## 实验范围

最终实验覆盖既有 391 题和四家模型。提交代码、两份完整提示、原始回包、初判、最终分类、调用数和延迟全部绑定保存。

21 题定向集合只可用于运行前的协议与证据链冒烟，不作为最终业务结论。最终需要逐题核对：

- A 错、C 对：纠正；
- A 对、C 错：破坏；
- A 与 C 都对：保持；
- A 与 C 都错：未解决；
- 协议、传输或预算失败：单独统计。

净收益为“纠正数减破坏数”，但仍须同时报告最终业务可接受数、合理不确定、错误和故障。
