# 来源校验与调用边界修补

以 `1d11d68c15d890920c7f51981aa52df406113e97` 为基线，只修确定性接口自身的问题。四道门、两轮回流、固定只读查询、认证主体及字段权限保持原职责。前端、外部学习与对账模块不在本轮范围。

## 改了什么

| 位置 | 已确认的问题 | 本次处理 |
| --- | --- | --- |
| 来源匹配 | “这周末”被拆成“这周”和“周末”，正确候选被误挡 | 同一文字区间内，登记的完整词覆盖其子词；分处不同区间的冲突条件仍拒绝 |
| 来源选项 | 既有选项缺少有限的同义来源 | 补充“明儿个”“这周末”“没取消”“还没还”；不增加业务类型、查询字段或整句分类器 |
| 资格失败交接 | JSON 合法，但名称或条件无法核验，也统一报协议故障 | 保留 `qualificationFailure`，第一轮返回现有必要澄清，第二轮仍不能核验则未知；未合格候选不查询 |
| 模型调用 | 截止时间固定，网络故障只有统一不可用 | 默认完整请求期限 18 秒，`QINGYE_LLM_TIMEOUT_MS` 可配置 100—18000 毫秒；分类记录 TIMEOUT、CONNECT、DNS、TLS、HTTP_STATUS 等 |

不同位置的条件不会因长词覆盖而被吞掉。例如“这周和这周末”“已领取未归还和已归还”仍不能压成一个选项。原文片段必须存在；字段、枚举、组合和权限校验继续执行。两条真正的结构/枚举违约没有放宽。

资格失败现在有真实的澄清凭据和回流路径，不只是改统计名称。回归测试验证补充后从第一门重进、保留任务和轮次，并执行新合格计划；第二轮仍未合格则停止。

模型提示词正文 `assistant-planner.txt` 未改。模型可见的合同元数据从同一配置生成，因此上述来源别名也会出现在新请求中。冻结回包复算不重新生成模型答案，能单独检验程序变化。
