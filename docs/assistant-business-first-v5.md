# 业务优先的四道门合同 v5

2026-10-22 用户确认的实现基线。旧版本与旧实验保留原资格；本文描述本轮目标，不把未完成测试写成通过。

## 职责与不变量

1. 初筛：校验认证、输入和明确业务入口。陌生名称或不认识的中文不等于域外；不建立中文关键词解释器。
2. 语义入口：首次只有确定与不确定。固定入口和表单无需模型；模型仅辅助定位已有业务集合及原话明确条件，必要时澄清。危险请求拒绝，仍不能理解则明确未知。
3. 有限协议与授权：服务器将定位转换为已有只读请求。身份来自认证会话；不接受 SQL、目标用户、任意操作或写能力。管理员使用助手也不扩大权限。
4. 确定性闭合：同一业务格子使用固定参数化查询、授权字段与同计划确认；本地不重新解释原句，不偷偷改目标、日期或状态。

格子是活动、器材、本人报名、本人借用等业务能力，不是社团或活动实例。新增数据不得要求更新规则或提示词。模型故障不影响已有目录、表单和固定入口。

当前接口实现为 v5.5：第三门可以将某字段内唯一匹配的合同选项标签规范化为对应 ID，例如“明天”到 `TOMORROW`；原话出处检查和能力限制继续生效。这不是重新扫描中文或增加同义词词典，也不能证明条件没有遗漏。

## 判断依赖与集合扩大

完整读取目标、否定、改口和条件后才形成候选。用户明确条件优先于推测；清楚的修正覆盖原条件，其他条件保留。冲突不能擅自取舍。具体思考顺序不是正确性保证。

能力必需输入由业务合同规定；用户明确要求即使不是接口必填也不能丢弃。非必要未知不参与决策，例如按活动名称查地点时没有必要猜日期。必要未知则澄清，不生成替代条件继续。

可以返回同一目标的完整授权对象或相关候选集合；不能把摄影换成 ART 大类、扩大权限、丢掉明确排除条件，或把候选说成已找到。没有日期默认全部活动时段由程序确定；器材当前库存是既有业务入口语义。没有匹配不等于不存在；分页不是查全或跨页快照。

## 澄清交互

- 每个请求最多主动提出五次澄清。只有必要未知才问，尽量一次集中询问；已确认条件保留。
- 模型只选择合同内固定问题类型，本地生成问题，不透传自由索敏或引导文案。原请求、历次问题与用户回答一起保留，答案不可成为系统指令。
- 第五次回答后若已确定，照常进入同计划范围确认。仍未确定则以 `CLARIFICATION_PAUSED / CLARIFICATION_LIMIT` 提示缺口并停止自动询问。
- 若模型明确表示仍无法理解，或问题与结构化候选均重复，可提前停下；仅文案相同但对象或条件已有变化不能算无进展。这是防循环条件，不是语义正确性证明。此状态不表示危险、拒绝或能力不支持。
- 取消弹窗不执行、不消耗回答次数；模型故障重试保留上下文，不把故障当语义失败。用户可以自主重新发起或使用原业务查询。
- 范围确认、分页和技术重试不计入澄清次数。会话、一次性凭据和有效期继续独立生效。

## 模型协议交接

收到模型响应但不符合协议时返回 `SYSTEM_ERROR / INVALID_PROTOCOL`，并用有限的 `protocolFailure` 标识原因；无配置、超时或外部服务不可用仍返回 `MODEL_UNAVAILABLE`。不把原始模型内容、内部异常文本或凭据透传到界面。

严格拒绝重复 JSON 成员（包括相同值）、未知字段、错误类型，以及同一筛选字段重复出现。对于两个时间角色不能表达为一个 `TIME` 的情况，不选择其中一个继续，也不自动修补、删条件或扩大集合。协议错误保留原请求、已问问题与回答，只有用户主动重试才再次调用；重试凭据绑定当前会话和请求且只能消费一次，不增加语义澄清次数。

错误分类与显式重试不等于模型协议输出已经修好。结构合法但漏掉明确排除条件仍是业务失败，不能靠解析器合法性宣布解决。

定位输出的字段、筛选项结构、长度上限、原因枚举与完整示例集中于 `assistant-locator-protocol.json`；提示词附加同一份元数据，解析器与定位对象校验引用该定义。它只描述模型交接格式，原 `assistant-contract.json` 的业务能力与权限不变；厂商请求仍使用 `json_object`，不声称厂商强制执行了完整 Schema。

验收分别保留安全、业务、协议三本账。提供相关候选集合和完成原查询是不同结果；不能把新交互路径的通过数代入旧自然语言回归。已确定业务对象仍重复询问、合法名称被误拒等均保留为未完成，不用安全边界通过抵消。

## 验收与证据边界

检查随机新增数据、断模查询、命名活动未加日期、硬条件保留、摄影不变艺术、相关候选、分页、五次边界、取消/重试/会话变化，以及跨用户和提示词注入。

程序可强制只读、身份和协议；提示词规定语义规则，不能证明模型遵守。真实模型业务结果与人工构造协议测试分别记账。合法 JSON、用户确认和真实数据库内容均不单独证明原意匹配；未测试与未知明确保留。

## 2026-10-23 阶段复验与收口

同一冻结题集对 DeepSeek 与千问各重复两次，共完成 372 次原生模型调用，HTTP 响应均成功。按原始用户需求而非模型自评计分：

| 观察项 | 次数 | 解释 |
| --- | ---: | --- |
| 形成预期查询 | 250 | 候选查询与冻结业务预期一致 |
| 正确停止 | 94 | 澄清、不支持或拒绝符合预期，不算完成查询 |
| 与冻结预期不符 | 28 | 包含第三门显式拦截和未完成语义转换 |
| 已观察写操作或读取他人私有数据 | 0 | 只覆盖本轮题集，不外推为普遍安全证明 |

28 次偏差中，第三门保留了 15 次协议或字段组合拒绝；另有两次千问把“今天借用”中的“今天”绑定为计划使用日期，形成结构、枚举、权限及来源片段均合法但业务角色错误的查询预览。范围确认能阻止未经用户确认的执行，却不能反向证明模型最初理解正确。`UNKNOWN / CLARIFICATION_PAUSED` 是多轮状态，本轮单轮题集未完整覆盖。

因此本阶段允许提交的是工程闭环及其有界证据：模型不拥有写权限、身份和事实；无模型时确定性业务入口仍可工作；第三、第四门不重新解释已确认计划；危险与未知可以安全停止。未解决的是跨模型、跨表达的通用语义一致性判定，特别是事件—时间角色绑定。该问题不继续扩张青野职责，作为 VeriTrail 的外部反例研究入口保存；不把 344/372 包装成全部业务通过，也不以正确停止抵消未完成查询。
