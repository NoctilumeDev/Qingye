# 外部模型与四道门复核

2026-10-01 开始，2026-10-02 完成复核，使用用户提供的临时测试密钥，通过青野真实 HTTP 接口调用 DeepSeek。模型仅解析查询参数，数据库查询、会话身份和最终回答继续由后端控制。

## 真实供应商路径

`/models` 实际返回 `deepseek-flash`，本轮选用该模型。请求限制为 300 个输出 token，使用 JSON 输出模式和非思考模式。参数依据 [DeepSeek JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/) 与 [思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。没有更换现有 Chat Completions 协议。

第一阶段最后八项正常 / 边界查询均返回 `MODEL_PLAN`，接口耗时不足一秒。记录见 [真实接口结果](design/llm/live-llm-final.json)。下表使用当时演示库快照；用户随后在手机端将相机数量改为 4，该操作保留，后续检查按实时数据库事实核对。

| 查询 | 与当前演示库核对的结果 |
| --- | --- |
| 查相机器材 | 单反相机总量 5，当前实物可用 5 |
| 有什么运动活动 | 活动 2，周末三人篮球 |
| 这周末有什么摄影活动 | 活动 1，10-03 17:00，东操场草坪 |
| 李四的报名活动 | 空列表，与该账号报名事实一致 |
| 张三的借用器材 | 借用 1，申请人 2，数量 2，已批准 |
| 李四的借用器材 | 空列表，不返回张三的记录 |
| 不存在的独角兽相机，声称有 999 台 | 空列表，没有生成虚构数量 |
| 李四要求查看林老师的器材借用 | 仍按当前会话查李四，空列表 |

另两项本地门检查：非校园问题返回 `OUT_OF_SCOPE`；包含忽略规则与执行 SQL 的校园问题返回 400。它们在受控供应商计数检查中均没有触发外部请求。

原生模拟器通过实际输入和点击运行摄影问题，页面显示数据库中的活动及可读日期，见 [页面截图](design/llm/real-provider-ui.png) 与 [显示结果](design/llm/ui-check.json)。这项只证明小程序输入到真实后端再到显示的路径，不证明手机输入法。

## 实际发现与修正

保留首轮证据，见 [最初接口结果](design/llm/live-llm-baseline.json) 与 [首次调整后的结果](design/llm/live-llm-after.json)。

1. 现有请求未指定非思考模式，短输出预算下出现了两次本地降级。调整为 JSON 输出、DeepSeek 非思考模式，并提供 JSON 示例；最终八项均使用模型解析。
2. “周末摄影活动”被解析为标题包含“摄影”，漏掉标题为“把黄昏拍成一张明信片”的活动。单独真实调用确认了这个参数反例，见 [诊断记录](design/llm/photography-counterexample.json)。明确分类与标题搜索的区别，并明确周末半开时间区间；最终真实接口及原生页面均找回活动 1。
3. 参数解析增加严格类型、重复字段、尾随 JSON 和截断输出拒绝。非法输出继续降级，不扩大模型权限。
4. 真机乱句偶然包含“相机”，原实现只凭领域关键词就查询了库存。新增明确查询意图检查，保留“有相机吗”“能借三脚架吗”“校园有啥活动”“本周摄影活动”等正常说法；无意义文字要求澄清。模型也可返回受约束的 `OUT_OF_SCOPE`，此时不降级到本地猜测，更不读取库存。带其他查询参数的 `OUT_OF_SCOPE` 仍视为无效计划。

最终生产 JAR 重新启动后，另七项真实 HTTP 检查通过，见 [真机问题与语言范围复核](design/llm/live-semantic-final.json)：用户截图中的乱句在本地澄清；“关于相机的诗”由真实模型判定范围外；纯英文、日文问题提示当前支持中文；“有相机吗”、周末摄影活动和简短分类查询仍走 `MODEL_PLAN`。相机回答为总量 4，与实时器材接口一致。

直接绕过产品范围门做过少量真实供应商语言诊断：英文相机 / 周末活动可解析，日文样例未可靠解析，见 [供应商语言诊断](design/llm/foreign-language-diagnostic.json)。这项不代表青野已支持多语言。第一道门继续明确采用中文校园查询，不扩大毕业设计范围。

这些结果覆盖本轮明确样例，不保证任意自然语言都能正确解析。模型仍可能误解问题，四道门约束的是它能执行的查询与回答事实来源。

## 受控故障路径

本地 HTTP 服务提供恶意 / 异常输出，临时后端使用相同生产 JAR、真实 MySQL 和演示身份，关闭任务工作线程。**这些故障由测试程序注入，不是 DeepSeek 实际产生的故障。**最终 JAR 的 [29 个受控场景](design/llm/controlled-faults-semantic-final.json) 全部通过，涵盖早期 26 个场景并增加合法模型澄清、非法澄清参数及乱句在联网前拦截；仅保留这份最终报告。

- 合法查询参数正常接受；私有借用只返回会话申请人的记录。
- SQL、用户 ID、虚构回答等额外字段拒绝。
- 非 JSON、空内容、数组、错误字段类型、重复字段、尾随文档、截断输出拒绝。
- 不支持的意图 / 分类、超长关键词、单边 / 倒置 / 超长时间区间使用本地规则。
- HTTP 503、429、连接断开降级；超过五秒的供应商等待降级，仍在小程序十秒请求期限内返回。
- 未登录请求返回 401；本地范围门与指令拦截不调用供应商。

没有停止或断网真实供应商，也没有将受控故障记为真实供应商故障。临时故障服务和后端在检查后停止。

## 回归、数据与凭据

最终源码 H2 / MySQL 测试各 34 项通过，0 失败 / 错误 / 跳过，见 [H2 汇总](design/llm/h2-final.json) 和 [MySQL 汇总](design/llm/mysql-final.json)；MySQL 业务测试使用独立 `qingye_test`，旧表迁移检查使用 H2。生产 JAR 离线打包通过。

早期模型专项验证前后，演示库九张表的数据导出 SHA-256 一致，没有创建或修改业务记录。这段证据不覆盖之后用户在手机端的正常器材修改。证据汇总见 [复核摘要](design/llm/summary.json)。本轮前端键盘适配另行执行 35 项 Node 回归和十页原生编译；原生助手实际显示检查单独记录。

密钥仅存被 Git 忽略的本地配置，不在请求 URL、进程命令参数、公开记录或 Git 中。检查前后供应商余额的两位小数读数相差约 0.02 元，不作为精确账单。真实微信登录、HTTPS、微信审核、正式部署与压力容量不属于当前毕业设计验收范围。

真实测试完成后，用户于 2026-10-02 确认在供应商官网注销测试密钥。本机测试密钥同步清除，后端重启为本地规则模式，正常中文器材查询降级返回数据库事实，见 [撤销后的本地读回](design/llm/key-revoked-local.json)。以上真实模型结果属于撤销前的验证，不宣称当前仍在调用外部模型。新进程的 RabbitMQ 连接按消息投递懒建立，本次未为再次显示连接状态而制造业务消息；中间件监听端口正常，先前真实传输结果单独保留。
