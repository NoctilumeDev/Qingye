## 本轮完成

- 公告入口放在首页“我的活动”与“问问青野”之间。用户可归档、恢复，管理员可发布、修改、删除管理员公告。
- 两条预置指引讲清楚怎么提问、没找对怎么办。管理员不能改删；项目用稳定 key 和递增 revision 更新，保留用户归档状态。
- 公告写入校验当前权限和内容版本；并发修改只允许一个旧版本请求成功，冲突时保留编辑草稿。删除隐藏公告并保留操作记录。
- 正式模式认证排除持久身份为 `demo:` 的账号，旧演示会话不能带入正式模式。
- 缓存不再把数据库查询放在全局锁里；失效代际阻止旧查询在删除后重新填回缓存。
- 正式启动入口固定关闭演示及可选中间件，检查必需配置，传播 Java 失败退出码。开发入口也修正了退出码。

实现与逐项审查见[公告与权限记录](governance/announcements-release-20261104.md)。

## HTTP 压测

单实例后端与 MySQL、压力客户端运行在同一台 Windows 电脑，i7-14650HX、约 16 GiB 内存；Java 堆上限 512 MiB、数据库连接池 8，Redis/MQ/模型关闭。

专用测试库含 103 个社团、3005 场活动、204 类器材、1004 条报名和 403 条借用。11 条读路径均衡混合，包括活动、器材、社团、公告、本人记录以及四类固定助手查询。每档预热 5 秒，测量 30 秒，每个 worker 同时只发一个请求。

| ---: | ---: | ---: | ---: | ---: | ---: |

| 8 | 48,550 | 1,617.4 | 22.3 ms | 27.8 ms | 0 |
| 32 | 49,524 | 1,649.2 | 39.2 ms | 49.6 ms | 0 |

测量合计 156,399 次请求。8 并发之后吞吐接近平台，延迟继续上升。这是该环境下的闭环只读负载结果；写入争用、独立到达流量、模型耗时与线上人数需要各自测量。数据、工具、JAR 散列和完整各接口结果见[压测报告](load-test-20261104.md)。
