# 青野

**校园社团活动与共享资源管理系统的设计与实现**

当前处于讨论和筹备阶段。本目录先记录项目方向，尚未创建应用代码、数据库或运行环境。下面的业务范围与技术细节仍需在开始实现前收敛。

## 项目方向

面向校园学生、社团负责人和管理员，围绕社团活动与共享器材形成一个规模有限的业务闭环：

> 组织活动 → 学生报名 → 申请借用器材 → 审核与领取 → 活动结束 → 归还器材

优先把这条主线做好。报名候补、通知和推荐等细节按实际需要确定，不把讨论过的所有功能都纳入第一版。

## 环境与工具

优先使用电脑上已经安装或缓存的工具和依赖，不另起一套环境，不使用 Docker。

| 部分 | 当前选择 |
| --- | --- |
| 前端 | 原生微信小程序：WXML、WXSS、JavaScript、JSON |
| 开发与预览 | 已安装的微信开发者工具 |
| 后端 | Java 17、Spring Boot 单体项目 |
| 构建 | 已安装的 Maven |
| 数据库 | MySQL 8.0 |
| 查询缓存 | 已安装的 Redis，可降级 |
| 消息队列 | 已安装的 RabbitMQ，可降级 |

具体依赖版本在开始实现时，以本机环境和兼容性核对结果为准。小程序直接通过 HTTP API 调用 Spring Boot；Node.js 不作为连接小程序与后端的业务服务。

客户端只做微信小程序，不使用 uni-app，不另做 Vue 网页、桌面端或独立手机应用。

## 设计边界

- **按变化原因组织代码。** 相对稳定的内容与经常变化的内容分开，因同一原因变化的代码尽量靠近。分层名称随实际需要确定，不先铺企业模板或完整 DDD 结构。
- **控制工作量。** 先确定功能清单和代码上限，再开始实现。目标约 6,000 行、上限 8,000 行是当前待确认的预算建议，统计手写后端、小程序、样式、SQL 和测试，排除依赖、生成文件和文档。
- **Redis 只加速查询。** 缓存不可用时回到 MySQL，库存、名额与业务状态仍以数据库为准。
- **MQ 处理通知等异步任务。** 业务事实与待处理任务保留在数据库；队列不可用时业务仍可完成，恢复后可补发，并避免重复处理。
- **大模型采用“四道门”。** 本地范围判断 → 受约束的意图与参数 → 参数化数据库查询 → 基于数据库事实回答。权限由后端校验，先限定为只读查询，模型不可用时降级。
- **算法先选一个。** 优先考虑简单、可解释、能与基础方法比较的活动推荐，具体算法另行讨论。

不拆微服务，不增加额外客户端，不把场地排期、复杂审批流等扩展方向自动变成必做功能。每次增加功能都要重新检查工作量，必要时删减其他内容。

## 界面方向

草坪绿、天空蓝与白色为主，少量红、橙、黄作为点缀。采用青春校园氛围的卡片、活动海报与器材展示，让学生在手机上方便浏览和操作。

学生、社团负责人和管理员使用同一个小程序，根据权限展示各自功能。不加背景音乐、天气弹窗等与业务主线无关的内容。
